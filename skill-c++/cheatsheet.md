# 速查表

> 写代码时摊在旁边看的那一页。术语定义去 `glossary.md`，手法去 `patterns.md`，
> 判断依据去 `chapters/`。

## 1. 所有权类型选型

| 类型 | 语义 | 拷贝 | 移动 | 什么时候用 |
|---|---|---|---|---|
| `T` | 值语义，自己拥有一切 | 深拷贝 | 移动 | **默认答案**，绝大多数数据成员 |
| `T&` / `T*` | 借用，不拥有 | 复制指针 | 复制指针 | 传参、观察者；**不要**存起来 |
| `std::unique_ptr<T>` | 唯一主人 | ✗ | ✓ | 默认的拥有型指针 |
| `std::shared_ptr<T>` | 共享主人 | ✓ | ✓ | 确有多方共享 |
| `std::weak_ptr<T>` | 观察者，不延长寿命 | ✓ | ✓ | 破 `shared_ptr` 环、缓存 |

> 指针 = 借用，智能指针 = 拥有。签名上要能一眼看出是哪种。

## 2. 传参方式

| 意图 | 写法 | 规则 |
|---|---|---|
| 只读入参 | `const T&`，小类型可按值 | F.16 |
| 要修改 | `T&` | F.17 |
| 接管所有权 | `T&&` + 内部 `std::move(x)` | F.18 |
| 完美转发 | `TP&&` + `std::forward<T>(x)` | F.19 |
| 输出 | **返回值**（多值返回结构体） | F.20 / F.21 |

## 3. 错误处理机制选择

| 场景 | 用 | 理由 |
|---|---|---|
| 调用失败是"预期内的正常分支" | 返回值 / `std::optional` | 调用方总要处理 |
| 失败是"不该发生但发生了" | 异常 | 栈展开自动释放资源（E.2） |
| 失败要跨 API 边界传给调用方 | `std::error_code` | 不可抛的上下文、嵌入式 |
| 失败是类型的一部分 | `std::expected<T,E>`（C++23） | 强制调用方处理 |

> **在接口边界选一种，然后一致到底**。不要在同一层混用。

## 4. 容器选型

| 需求 | 选 | 注意 |
|---|---|---|
| 默认 / 顺序访问 / 连续内存 | `vector` | 扩容会使迭代器失效 |
| 两端增删 | `deque` | 元素不连续 |
| 按键查找、有序遍历 | `map` | 节点式，缓存不友好 |
| 按键查找、只要快 | `unordered_map` | rehash 失效迭代器；哈希碰撞 |
| 只在头部增删 | `list` | 缓存不友好，多数场景 `deque`/`vector` 更好 |
| 去重集合 | `set` / `unordered_set` | 同上 |

## 5. 迭代器失效

| 容器操作 | 失效范围 |
|---|---|
| `vector` 扩容（`push_back` 等） | 全部 |
| `vector` 元素被删 | 被删位置及其后 |
| `map` / `set` 删元素 | 仅被删那个 |
| `unordered_*` rehash | 全部（rehash 前后都可能） |
| `deque` 中间插入 | 全部 |

> 循环里 `push_back` 是经典 UB。写不出安全形式就用索引遍历。

## 6. 性能优化优先级

```
1. 算法复杂度（O(n²) → O(n log n)）   ← 收益最大
2. 数据结构选择（vector vs list vs map）
3. 内存布局 / 分配次数（热点路径避免分配，Per.15）
4. 常数因子（缓存友好、避免分支预测失败）
```

> 没 profiler 数据就不动手（Per.1/Per.2）。先测再改。

## 7. 门禁命令

| 目的 | 命令 | 查什么 |
|---|---|---|
| 编译期 | `-Wall -Wextra -Wpedantic -Werror` | 隐式转换、未使用变量、UB 嫌疑 |
| 内存 + UB | `-fsanitize=address,undefined` | 越界、UAF、泄漏、整数溢出 |
| 数据竞争 | `-fsanitize=thread` | 竞争、锁顺序 |
| 规则号引用 | `python scripts/rule_lint.py <路径>` | 写错的 Core Guidelines 编号 |

## 9. Tells & smells（看到就该警觉）

| 你看到 | 大概率是 |
|---|---|
| 函数返回 `const T&` 且内部有局部变量 | 悬垂引用 |
| 裸 `new` / `delete` 成对出现 | 异常路径上泄漏 |
| `std::remove` 后面没有 `erase` | 元素根本没被删 |
| 类的析构函数不是 `virtual` 但有派生类 | 经基类指针 delete 泄漏 |
| `for (int i = 0; i < v.size(); ++i)` | 有符号/无符号比较 |
| `auto x = ref;`（ref 是引用） | 意外深拷贝 |
| 手动 `lock()` / `unlock()` | 异常或早退时死锁 |
| 用 `volatile` 做线程同步 | 完全没有同步 |
| `shared_ptr` 成员互相指向 | 引用计数永不归零 |
| 移动构造/赋值没标 `noexcept` | `vector` 扩容退化成深拷贝 |
| 宏参数出现在表达式里 | 参数求值两次 |
| 跨翻译单元的全局非平凡对象 | 静态初始化顺序未定义 |
| 浮点用 `==` 比较 | 几乎总是不成立 |

## 10. 动手前问自己三句

1. **这块内存谁负责释放？**（答不出来就别写）
2. **这里会多线程吗？**（默认会）
3. **这个判断有工具能验吗？**（能就交给工具，别靠人肉记）
