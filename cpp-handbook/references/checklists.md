# 分环节自检清单

按环节取用，不必全跑。每条后面的括号是 Core Guidelines 规则号或知识库指针。

---

## 设计期（写代码之前）

- [ ] 错误处理策略定了吗？（E.1）异常表示什么？返回值表示什么？
- [ ] 每块资源的主人是谁？——这一条没答案就不要动手。（R.20/R.21）
- [ ] 对象的不变量是什么？构造完必须成立。（C.41）
- [ ] 接口需要拷贝语义还是引用语义？值类型别塞智能指针。（F.7/F.16–F.19）
- [ ] 需要共享吗？只是"到处传同一个对象"的话，先想想 unique_ptr + 明确管理者。（R.21/R.24）
- [ ] 这段代码会跑在多线程下吗？（CP.1）默认会。

## 编码期（写完每一块）

- [ ] 有裸 `new`/`delete` 吗？→ 换 `make_unique`/`make_shared`。（R.11）
- [ ] 有返回局部对象引用/指针的函数吗？→ 改按值返回。（F.43）
- [ ] lambda 捕获了 `this` 或引用吗？被捕获对象活得比 lambda 久吗？
- [ ] 移动构造/赋值标 `noexcept` 了吗？
- [ ] 长度和下标是 `std::size_t` 吗？有没有有符号/无符号比较？
- [ ] 多态基类有虚析构吗？拷贝/移动被抑制了吗？（C.67）
- [ ] `= delete` 不可拷贝时，拷贝构造**和**拷贝赋值都写了？（C.21）
- [ ] 宏在表达常量或函数吗？→ 换 `constexpr`。（ES.31）
- [ ] 头文件里有非 inline 函数定义或非模板变量定义吗？（SF.5）
- [ ] 锁是用 RAII 包的吗？多个锁是不是 `std::scoped_lock`？（CP.20/CP.21）
- [ ] 输出参数能不能改成返回值？（F.20/F.21）

## 评审期（看别人的代码）

按严重度排序，别把风格问题和正确性问题混在一起说：

1. **正确性**：UB、悬垂、数据竞争、越界、整数溢出 —— 先看 `topics/pitfalls-and-antipatterns.md`
2. **所有权**：谁释放、有没有环、借用有没有被存起来 —— 看 `topics/ownership-and-lifetime.md`
3. **接口**：传参方式、错误传递、扩展性
4. **可读性**：命名、注释、层次 —— 命名按项目约定，别拿个人偏好当缺陷

给结论时附上依据：规则号，或 `knowlege/` 下的文件路径。

## 上线前（门禁）

```bash
# 编译期
-Wall -Wextra -Wpedantic -Werror

# 内存 / 未定义行为
-fsanitize=address,undefined

# 数据竞争（多线程程序必跑）
-fsanitize=thread
```

- [ ] 零警告编译通过？
- [ ] ASan + UBSan 跑过全部测试？
- [ ] 有并发的部分跑过 TSan？
- [ ] Release 构建跑过？（Debug 下不出现的 UB 在 Release 下常显形）
- [ ] 规则号引用无 lint 错误？`python scripts/rule_lint.py <路径>`

## 排查顺序（崩溃 / 死锁 / 结果不对）

1. 先上工具，再看代码：
   - 崩溃 → ASan（堆越界、UAF、泄漏）
   - 结果不对但没崩 → UBSan（整数溢出、非法移位、UB 移位）
   - 偶发错乱 → TSan（数据竞争）
   - 死锁 → `gdb` 线程栈，或 `perf` 看热点
2. 工具没报出来时，看"合法但诡异"的那一类 UB：
   - 有符号溢出、`i = i++`、越界读（可能看起来是对的）
   - 静态初始化顺序问题
   - 迭代器失效
3. 再查 ABI / 未定义行为假设（严格别名规则、类型双关）。

> 工具链细节见 `knowlege/topics/toolchain-and-debugging.md`。
